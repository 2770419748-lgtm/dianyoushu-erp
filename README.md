# 店有数 ERP

[![CI](https://github.com/2770419748-lgtm/dianyoushu-erp/actions/workflows/ci.yml/badge.svg)](https://github.com/2770419748-lgtm/dianyoushu-erp/actions/workflows/ci.yml)

手机零售门店经营系统的演示版：从采购入库、串号库存、调拨盘点、门店开单（含以旧换新）到收银日结、经营看板，一条业务链跑通。四种角色各看各的数据，店员用手机扫码开单。

和桌面版“店有数”（仓库 `dianyoushu`，已经在门店日常使用的经营数据工具）是两个项目：桌面版给一家店自己用，店有数 ERP 是多门店、多角色、带完整进销存链路的版本。

这 4 个账号受保护（演示模式 `DEMO_MODE` 默认开），不能被改密码、停用或改角色；想试这些功能先用 `hq` 新建一个员工。`demo1234` 只是演示用的公开密码：本机和上线后的演示站都用它，演示站每天重置数据；拿去给真实门店用之前先过一遍 `docs/部署.md` 开头的“上线前检查清单”（第一条就是关演示模式、改掉所有密码）。

## 做了什么

| 模块 | 能做什么 |
|---|---|
| 登录与权限 | 账号密码登录、错 5 次锁 15 分钟；四种角色，数据范围在服务端按门店过滤；操作日志 |
| 组织 | 区域 → 门店 → 员工三级树，新增、编辑、停用、重置密码 |
| 商品 | 品类、品牌、型号、SKU（颜色、容量）；指导价 + 门店售价 |
| 采购入库 | 采购单草稿 → 提交 → 到货（可分批）；每台机器录 SN、IMEI1、IMEI2，可粘贴可扫码 |
| 库存 | 串号库存、配件库存、低于安全库存标红；每次增减都有流水，一台机器从入库到卖出全程可查 |
| 调拨与盘点 | 申请锁定 → 发出在途 → 按码收货；盘点快照应有、录实盘、自动算盘盈盘亏 |
| 开单 | 电脑版：选客户、加机器配件、改价优惠、以旧换新抵扣、多种收款拆分；手机版：扫码加商品、一屏提交 |
| 回收与退货 | 现场收旧机抵扣、回收机转良品再卖；按原单退货、按原收款方式退款 |
| 企业微信（模拟演示） | 员工填企业微信账号；开单后生成只认这个客户的加微二维码，客户扫码加店员就绑到档案（不按手机号猜）；加好友立刻发欢迎语、删好友分清谁删谁；回调验签、解密、去重。演示站不连企业微信，点“模拟客户扫码加好友”走一遍真实的回调处理；设 WECOM_ENABLED=1 即真对接；聊天侧边栏：员工在企业微信里看当前客户的订单、机器保修、碎屏险延保，没绑定的按完整手机号认领，登录用侧边栏自己的票、只能看自己的好友；微信客服自动答复：按关键词答营业时间地址、保修、理赔、机型价格和哪些区域有货、我的保障（只答绑定过的客户），要人工或连着两句没听懂就转人工，守企业微信 48 小时 5 条的规定；客户继承：店长、总部在客户详情里转接跟进人，停用员工马上生效、他的企业微信客户交给接手人，结果每天查回来 |
| 售后维修 | 接件扫码带出购买记录、保修和碎屏险；检测报价时系统校验谁能付（保修 / 碎屏险 / 延保 / 自费）；修好取机结算，收款进当天日结；碎屏险理赔一次就用掉；客户的机器不动库存 |
| 运营商业务 | 号卡、合约机、宽带登记一笔记一笔，佣金按总部配的政策记预计；总部每月导入运营商结算单自动对账，标出金额不符、我们没登记、运营商漏给和返销扣回；运营商不开放接口，演示里用模拟的状态同步和结算单 |
| 国补 | 总部配政策（手机、平板 15%、单件最多 500 元、6000 元以内）；开单填顾客的资格码，系统校验每人每类一台、算补哪台补多少，记一笔“国补立减”；国补单从提交审核到平台到账全程跟踪，退货只退顾客付的部分、国补单跟着撤销；各省平台不开放，演示里审核和到账是模拟的，真用导入平台结果表格 |
| 发票 | 销售单上申请开票（电子普票、电子专票、纸质普票，抬头自动带出上次的），明细按商品 13%、服务 6% 算税额；总部开具（演示里模拟数电票号码，真用时登记电子税务局开好的号码）；退货作废后自动标需红冲；国补审核自动带发票号码 |
| 审批 | 总部按场景配规则（开单让利、低于成本卖、大额退款、作废、大额调拨、盘亏，默认全关）；触发了就先存审批单，店长或总部批了，系统以发起人身份按当时的数据把事做掉，做不成的写明原因；同一件事只能一张待审批 |
| 服务权益 | 碎屏险、延保开单自动记保障到期日（不扣库存、必须选客户、选保哪台机器）；客户详情看保障和买过的单；到期名单按剩 0～7 天、8～30 天两档提醒，门店记“已联系” |
| 日结 | 按支付方式对账、逐单比对、差异标红、确认后锁单，收银日报导出 |
| 看板 | 日销趋势、门店月销对比、员工排名、热销机型、KPI 完成率与每天还差多少、库存周转与滞销 |
| 其他 | KPI 目标录入、后续规划页（没做的模块和原因）、PWA 可添加到手机桌面 |

模拟数据：10 家店、100 个员工、截至昨天 3 个月约 1.2 万张销售单、1500 张回收单，全部随机生成，不含真人信息。

## 技术

Next.js 16（App Router）+ TypeScript + Prisma 7 + PostgreSQL 17 + Ant Design 6 + ECharts；单仓库单进程，业务规则全部在 `src/server/` 服务层。测试：Vitest（单元测试和连库测试，跑完回滚）+ Playwright（电脑开单到日结、手机开单两条端到端）；GitHub Actions 起一个临时 PostgreSQL，跑 lint、类型检查、全部测试（含连库、并发、回归）、对账自检和生产构建。部署用 Docker Compose（PostgreSQL + 应用 + Caddy 自动 HTTPS + 每日备份，带健康检查 `/api/health` 和日志限额），写好了还没上线。对账自检 `pnpm db:check`，每日任务 `pnpm daily`（到期提醒、企业微信清理），压测 `pnpm load-test`（先起生产构建）。

为什么这么选、为什么不做 App 和人事：`docs/取舍记录.md`。

## 本地运行

1. 装好 Node 24、pnpm、PostgreSQL 17，在 PostgreSQL 里建一个空库 `dianyoushu_erp`。
2. 把 `.env.example` 复制一份改名 `.env`，填上数据库密码和一串随机的会话密钥。
3. `pnpm install`（装完会自动生成 Prisma 客户端）。
4. `pnpm db:migrate` 建表。
5. `pnpm db:reset` 灌入模拟数据，约 30 秒。
6. `pnpm dev`，浏览器打开 http://localhost:3000 。

## 手机上测试

手机浏览器只在 HTTPS 页面里给摄像头，扫码要这样开：

1. 电脑和手机连同一个 Wi-Fi。
2. 关掉 `pnpm dev`，改跑 `pnpm dev:https`。第一次会用 openssl（装了 Git for Windows 就有）给电脑的局域网 IP 签一张本机测试证书，不装根证书、不改系统设置。
3. 手机浏览器打开终端里打印的地址（例如 `https://192.168.1.8:3000`），提示“不安全”时点“高级 → 继续访问”。Windows 弹防火墙提示选“允许”。
4. 登录后点首页的“手机开单”或“查库存”，点“扫码”对准串号条码。想像 App 一样用：浏览器菜单里选“添加到主屏幕”。
