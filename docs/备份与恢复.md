# 备份与恢复（本机）

上服务器之后再把备份推到对象存储，见 `部署.md`。本机这一套先保证两件事：每天有备份；备份真的能恢复。

## 备份

```bash
pnpm db:backup
```

- 用 PostgreSQL 自带的 `pg_dump` 导出一份压缩备份（`-Fc` 自定义格式），文件名带北京时间，例如 `dianyoushu_erp-20261017-084012.dump`。
- 默认放在代码目录旁边的 `备份` 文件夹（`D:\店有数ERP系统\备份`），不在仓库里，不会被提交。要换位置就设环境变量 `BACKUP_DIR`。
- 只留最近 14 份，更早的自动删掉。
- 数据库密码从 `.env` 读，通过环境变量 `PGPASSWORD` 传给 `pg_dump`，不出现在命令行和日志里。

## 恢复演练（不动正在用的库）

```bash
pnpm db:restore-check            # 用最新一份备份
pnpm db:restore-check 某个.dump   # 指定一份
```

把备份恢复进临时库 `dianyoushu_erp_restore_check`，逐表对比行数，打印对照表，最后删掉临时库。改过表结构（加了迁移）之后跑一次，确认备份还能用。

2026-10-17 第一次演练：32 张表、约 13 万行全部恢复，行数与现库一致。

## 真出事了怎么恢复到正式库

先停掉应用，再用 `--clean` 覆盖：

```bash
# Windows 默认安装路径；密码会提示输入
"C:\Program Files\PostgreSQL\17\bin\pg_restore.exe" -h localhost -U postgres -d dianyoushu_erp --clean --if-exists --no-owner 备份文件.dump
```

`--clean` 会先删掉库里的同名表再建，库里比备份新的数据会丢，所以恢复前先 `pnpm db:backup` 一份现状。

## 每天自动备份

用 Windows 自带的“任务计划程序”，每天晚上 23:30 跑一次。在 PowerShell 里执行一行（只需一次）：

```powershell
schtasks /Create /TN "店有数ERP 每日备份" /SC DAILY /ST 23:30 /TR "cmd /c cd /d D:\店有数ERP系统\code && pnpm db:backup >> D:\店有数ERP系统\备份\backup.log 2>&1"
```

- 查看：`schtasks /Query /TN "店有数ERP 每日备份"`
- 删除：`schtasks /Delete /TN "店有数ERP 每日备份" /F`
- 电脑当时关机就跳过那一天；演示数据随时能用 `pnpm db:reset` 重新生成，丢一天问题不大。
