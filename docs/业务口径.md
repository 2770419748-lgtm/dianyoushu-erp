# 店有数 ERP：业务口径 v0

- 版本：v0，2026-10-16
- 状态：坤总决定先按 AI 给的默认口径推进（原话："口径暂时用你提供的默认的"）。每条后面标【默认】的都是默认做法，坤总逐条确认后改成【已确认】；要改的直接改本文件，再改代码。
- 用法：每个开发任务先读对应小节。本文件和《手机零售ERP演示版方案》冲突时，以本文件最新版为准，并在《任务清单》末尾"变更记录"登记。
- 术语：大件 = 按串号一机一码管理的商品（手机、平板、电脑）；小件 = 按数量管理的商品（配件、号卡等）；串号 = IMEI，15 位数字。

## 1 角色与权限

四种角色：店员、店长、区域经理、总部。一个账号只有一种角色。

**数据范围**（服务端统一校验，不靠前端藏菜单）：

| 角色 | 能看的范围 |
|---|---|
| 店员 | 本店 |
| 店长 | 本店 |
| 区域经理 | 所辖区域下所有门店 |
| 总部 | 全部门店 |

**操作权限**【默认】：

| 功能 | 店员 | 店长 | 区域经理 | 总部 |
|---|---|---|---|---|
| 开单、退货、回收单、查客户 | ✓ | ✓ | – | ✓ |
| 查库存、查串号流水 | ✓ | ✓ | ✓（辖区） | ✓ |
| 盘点录入 | ✓ | ✓ | – | ✓ |
| 盘点确认 | – | ✓ | – | ✓ |
| 调拨申请、发出、收货 | – | ✓ | – | ✓ |
| 作废销售单、回收单 | – | ✓ | – | ✓ |
| 改门店售价 | – | ✓ | – | ✓ |
| 日结录入与确认 | – | ✓ | – | ✓ |
| 回收机转良品 | – | ✓ | – | ✓ |
| 看板、报表 | 本店 | 本店 | 辖区 | 全部 |
| 商品主数据、采购单与入库、组织管理、KPI 目标、后续规划页 | – | – | – | ✓ |

区域经理只看不做，是管理视角。总部账号为了演示方便什么都能做，真实系统里会再拆采购、财务等岗位。

## 2 组织

| 对象 | 字段 | 说明 |
|---|---|---|
| 区域 | 名称、状态 | 一级，不分子区域【默认】 |
| 门店 | 编码（如 S001）、名称、所属区域、地址、状态（营业/停用） | 不分直营/加盟、不分等级【默认】 |
| 员工 | 姓名、登录账号、角色、所属门店、所辖区域、在职状态 | 员工就是登录用户；店员和店长必填所属门店，区域经理必填所辖区域，总部两项都空 |

停用、离职只改状态，不物理删除；历史单据上的人和店要能追溯。

## 3 商品

- 品类：一级，带"大件/小件"标记【默认】。大件：手机、平板、电脑；小件：保护壳、贴膜、充电器、耳机、号卡等。
- 品牌：华为、苹果、小米、荣耀、OPPO、vivo 等。
- 型号：品牌 + 品类 + 名称，如"华为 Mate 70"。版本差异（标准版 / Pro）当作不同型号【默认】。
- SKU = 型号 + 颜色 + 容量【默认只有这两个规格】，带条码（可空）、指导价、参考成本。小件的 SKU 通常只有一个规格或没有规格。
- 门店售价：按门店覆盖指导价，没设就用指导价；店长和总部能改【默认】。
- 串号：15 位数字 IMEI，全局唯一，一台机器一条记录，记录入库成本。（2026-10-16 坤总提出大件要三个码：86 码、IMEI1、IMEI2，待他回答细节后改）
- 小件安全库存：按 SKU 设一个数，门店数量低于它在库存页标红，0 = 不预警【默认】。

## 4 串号状态机

状态：在途、在库、已售、回收、良品、锁定、盘亏。比方案多一个"盘亏"，因为盘点确认少了一台时机器要有个终态，否则库存余额和流水对不上【默认，影响方案 6.4】。

| 当前状态 | 动作 | 变成 | 说明 |
|---|---|---|---|
| （无） | 采购到货入库 | 在库 | 归属 = 收货门店 |
| 在库 | 调拨申请提交 | 锁定 | 锁定后不能开单，防止申请到发出之间被卖掉 |
| 锁定 | 调拨发出 | 在途 | 归属仍是发出店 |
| 锁定 | 调拨作废 | 在库 | 解锁 |
| 在途 | 调拨收货 | 在库 | 归属改为收货店 |
| 在库 | 开单提交 | 已售 | 在一个事务里扣库存、写流水、记收款 |
| 已售 | 销售单作废 | 在库 | 日结确认后不能作废 |
| 已售 | 退货 | 在库 | 退回原门店 |
| （无） | 回收单提交 | 回收 | 旧机进本店回收库，成本 = 估价 |
| 回收 | 检测转良品 | 良品 | 店长或总部确认 |
| 良品 | 开单提交 | 已售 | 良品可以再卖 |
| 在库 / 良品 | 盘点确认盘亏 | 盘亏 | 流水 −1 |
| （无） | 盘点确认盘盈 | 在库 | 要填串号和 SKU，流水 +1 |

只有"在库"和"良品"能开单；在途、锁定、回收、盘亏都不能卖。状态机之外的跳转一律拒绝。

## 5 单据与状态

单号 = 前缀 + yyyyMMdd + 4 位当日流水，如 `SO202610160001`。前缀：采购 PO、入库 RI、调拨 TR、盘点 ST、销售 SO、退货 RT、回收 RC、日结 DC。

| 单据 | 状态流转 | 规则【默认】 |
|---|---|---|
| 采购单 | 草稿 → 已提交 → 已到货；草稿或已提交可作废 | 总部开；可多次到货，全部到齐自动变已到货 |
| 入库单 | 已完成 | 一次到货一张；大件粘贴串号批量录入，校验 15 位数字和全局唯一；小件按数量；不作废，录错用盘点或退货处理 |
| 调拨单 | 申请 → 已发出 → 已收货；申请中可作废 | 申请时串号锁定；发出变在途；收货逐个核对串号，可部分收货，没收到的留在在途，全部收齐整单变已收货 |
| 盘点单 | 进行中 → 已确认；进行中可作废 | 建任务时快照"应有"，录入实盘串号或数量，自动算差异，确认后盘盈盘亏写流水 |
| 销售单 | 已完成 / 已作废 | 提交即扣库存，一个事务完成；作废恢复库存并留痕；日结确认后当日单据锁定不可作废 |
| 退货单 | 已完成 | 选原销售单，串号回在库、小件加回数量，记负数收款；退货单本身不作废，退错了再开一单 |
| 回收单 | 已完成 / 已作废 | 已被抵扣或已转良品的不能作废 |
| 日结 | 未确认 → 已确认 | 按门店按日；确认后当日销售单、退货单锁定 |

所有单据不物理删除，只能作废，作废记录谁、什么时候、为什么。

## 6 支付方式

现金、微信、支付宝、刷卡、分期、以旧换新抵扣、其他【默认：分期不细分，不做国补】。

- 一张销售单可以拆多种支付方式，各项合计必须等于应收，差一分都不能提交。
- 退货的退款记负数、记在原支付方式上；含以旧换新抵扣的单退货时，抵扣部分不退（旧机已回收不退还），只退实付金额【默认，待确认】。

## 7 以旧换新

- 估价由店员手填，不按机型表【默认】。
- 回收单提交后：旧机进本店回收库，串号状态"回收"，成本 = 估价。
- 开单时可以关联一张回收单，抵扣金额 = 估价，作为"以旧换新抵扣"这种支付方式计入支付明细；抵扣不能超过本单应收；一张回收单只能抵扣一张销售单。
- 回收机检测后由店长或总部确认转良品，良品可以再开单卖出，卖出毛利 = 售价 − 估价。

## 8 客户

姓名、手机号（唯一，用来查找）、备注。列表和详情里手机号脱敏显示（138****1234），只有开单当下看得到全号【默认】。模拟数据不用任何真人信息。

## 9 KPI 口径

从店有数口径库搬演示要用的，去掉运营商相关（印象+、新合约、佣金）【默认】。目标按"门店 × 月"录入（第 10 周）。

| 指标 | 定义 | 来源 |
|---|---|---|
| 销售额 | 当期已完成销售单应收合计 − 退货退款合计 | 销售单、退货单 |
| 毛利（总毛） | 销售额 − 售出商品成本；大件成本按串号入库成本或回收估价，小件按参考成本 | 销售明细的成本快照 |
| 主机量 | 售出大件数量（手机、平板、电脑），退货扣减 | 销售明细 |
| 旧机回收 | 当期回收单台数【默认按台数；店有数按金额考核，待确认】 | 回收单 |
| 单贡 | 毛利 ÷ 主机量 | 派生 |
| 时间进度 | 销售数据截止日的日序号 ÷ 当月自然日总数（店有数口径） | 派生 |
| 完成率 | 实际 ÷ 目标 | KPI 目标 |
| 门店日均差额 | （目标 − 实际）÷ 剩余天数 − 已过去天数的日均实际；正数表示后面每天要比现在多卖多少 | 派生 |

## 10 操作日志

记谁、什么时候、做了什么、对哪条记录。第 2 周先记：登录、登出、组织变更；后续加单据作废、日结确认、价格修改。

## 11 必须守住的规则（来自方案 6.5）

1. 串号全局唯一，状态只能按第 4 节的表走。
2. 所有库存变化走库存流水，不直接改余额；余额永远能从流水算出来。
3. 开单扣库存、记收款、写流水在一个数据库事务里，失败全部回滚。
4. 单据不物理删除，只能作废，作废留痕。
5. 金额用整数"分"存。
6. 权限在服务端校验。
