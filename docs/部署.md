## 结构

一台服务器、一个 `docker compose`：

| 服务 | 干什么 |
|---|---|
| `db` | PostgreSQL 17，数据存在 `pgdata` 卷里 |
| `app` | 本仓库的 Next.js 应用（`Dockerfile` 三段构建，standalone 输出） |
| `caddy` | 反向代理；`SITE_ADDRESS` 是 `:80` 时用 IP 访问，是域名时自动申请 HTTPS 证书 |
| `tools` | 平时不启动；跑迁移、灌演示数据时临时用 |

## 第一次部署

```bash
# 1. 服务器上装 Docker（Ubuntu 24.04）
curl -fsSL https://get.docker.com | sh

# 2. 拉代码
git clone https://github.com/2770419748-lgtm/dianyoushu-erp.git && cd dianyoushu-erp

# 3. 写 .env（不进仓库）
# 两个随机串用 openssl rand -base64 32 各生成一个（SESSION_SECRET 少于 32 个字符应用会拒绝启动）
cat > .env <<'ENV'
POSTGRES_PASSWORD=换成一长串随机字符
SESSION_SECRET=换成另一长串随机字符
SITE_ADDRESS=:80
ENV

# 4. 起数据库、建表、灌演示数据（约 1 分钟）
docker compose up -d db
docker compose run --rm tools pnpm exec prisma migrate deploy
docker compose run --rm tools pnpm db:reset

# 5. 起应用和 Caddy
docker compose up -d --build app caddy
```

浏览器打开 `http://服务器IP`，用 README 里的演示账号登录（登录 cookie 会按实际协议决定要不要加 Secure，纯 http 也能登录；上了 HTTPS 后自动加）。应用起不来时先看 `docker compose logs app`：配置不合格（会话密钥太短、还是占位值、没配数据库）会打印“配置不合格，拒绝启动”和具体原因。

## 演示账号和密码

- 演示站上 hq、regional、manager、staff 四个账号和密码 `demo1234` 是故意公开的，给面试官自己点。它们不能被改密码、停用、改角色，每天凌晨重置一次数据。
- 除了这四个，模拟数据里其他员工账号的密码也是 `demo1234`，同样每天重置。
- 不要在演示站上录真实数据。哪天拿这套代码给真实门店用，要先改掉所有账号的密码（或者不跑 `pnpm db:reset`、自己建账号），并把演示账号停用（先删掉 `src/server/auth/demo-accounts.ts` 里的保护名单）。

## 备案下来、有域名以后

1. 域名解析：A 记录指向服务器 IP。
2. `.env` 里 `SITE_ADDRESS=你的域名`，然后 `docker compose up -d caddy`，Caddy 会自动申请证书，`https://你的域名` 就能打开。
