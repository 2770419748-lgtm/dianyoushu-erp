# 取舍记录

每条三句话：选了什么、为什么、代价是什么。面试被问“为什么这么做”时照这个讲。

## 技术选型

**为什么选 Next.js 全栈，不做前后端分离**
一个人维护，前后端放在一个 TypeScript 仓库里，页面和服务端共用类型，改一个字段编译器就能把两边都查出来。页面提交走 Server Function，省掉了一层手写接口和接口文档，部署也只有一个进程。代价是和 Next.js 绑得比较深；所以业务规则全放在 `src/server/` 的服务层，不写在页面里，真要拆成独立后端时搬服务层就行。

**为什么选 PostgreSQL**
进销存最怕数据对不上，需要事务、唯一约束、外键这些数据库本身就能保证的东西。串号全局唯一、日结一店一天一条，都是用数据库的唯一索引兜底，不只靠代码判断。看板的统计用 SQL 直接聚合，1.2 万单在 0.5 秒内出结果。

**为什么用 Prisma**
表结构写在一个文件里，自动生成带类型的查询代码，字段写错编译就报错。迁移文件进仓库，谁拉代码都能一条命令建出一样的表。复杂的统计查询（看板）不用它的查询构造，直接写 SQL，用它的参数化防注入。

**为什么用 Ant Design**
ERP 页面主要是表格、表单、弹窗，Ant Design 这些组件齐全，中文文档全，国内后台系统最常见。表格自带分页、横向滚动，手机上也能看。代价是包比较大、样式是运行时注入的，所以没上严格的 CSP。

**为什么登录自己写，不用 Auth.js**
只有账号密码一种登录方式，自己写也就是 bcrypt 存哈希、签一个 JWT 放进 httpOnly cookie，代码少、每一行都讲得清。限流放进程内存里，单进程部署够用，重启清零是已知取舍。令牌不依赖 cookie 校验，以后做 App 改成请求头传就能复用。

## 业务规则

**为什么金额用整数“分”**
小数在计算机里有精度误差，0.1 + 0.2 不等于 0.3，收银对账差一分都不行。所有金额存整数分，只在显示时除以 100。拆分收款、退款分摊这些计算全在整数上做；退款按优惠比例分摊时四舍五入到分，且不能超过“实付 − 已退”，规则都在 `src/server/sales/payments.ts` 的纯函数里，有单元测试。

**为什么库存不直接改余额，而是走流水**
每一次增减（入库、调拨、开单、退货、盘点）都写一条流水，余额只是流水的累计。这样任何一台机器从入库到卖出每一步都查得到，余额对不上时能从流水算回来。模拟数据生成完会自检“余额 = 流水累计”，不为 0 就算失败。

**为什么单据只作废不删除**
删了就没法对账，也查不出是谁动的。作废会恢复库存、写反向流水、记录谁什么时候为什么作废。日结确认后当天的单据锁定，连作废都不行，要先由总部撤销日结。

**并发怎么防：条件写入 + 数据库约束 + 同店同日排队**
两个店员同时卖同一台机器，如果代码是“先读状态、判断在库、再改成已售”，两边都会读到“在库”、都卖成功。现在改机器状态时把“状态还是刚才读到的那个”写进更新条件，改到 0 行就说明被别人抢先了，整单回滚；配件出库用“余额够才减”的原子更新，数据库上再加“余额不能为负”的检查约束兜底。开单、作废、退货和日结确认对同一家店同一天用 PostgreSQL 的事务级咨询锁排队，没有用全库“可串行化”隔离级别，因为那样所有门店都要互相等、还要处理重试。

**登录限流按用户名，不按 IP**
没有反向代理时请求里的“来源 IP”可以伪造，按 IP 限流等于没限；不带这个头时大家又会被算成同一个 IP，一个人输错 5 次全店一起被锁。所以只按用户名锁：错 5 次锁这个账号 15 分钟，代价是别人可以故意输错把某个账号锁住，演示版接受。4 个公开的演示账号不限流，密码本来就是公开的。

**改价不设下限、不要审批**
门店里改价很常见（老客优惠、凑整），每次都等店长批会卡住收银。现在的做法是改价照常，但单据上同时存原价和成交价、改过的标出来、写进操作日志，事后可查。真要管住，下一步是“低于某个比例要店长输密码确认”。

**为什么大件存三个码**
一台手机盒子上有 SN、IMEI1、IMEI2，店员手里拿到哪个扫哪个，系统要都认得。三个码各自全局唯一，主码按 IMEI1、SN、IMEI2 的顺序取，列表和链接统一用主码。不要求三个都填，只录一个也能入库。

## 范围

**为什么不做 App**
门店用手机浏览器打开，加上“添加到主屏幕”全屏打开，已经够用，不用过应用商店审核。一个人同时维护网页和两个原生 App 不划算。路留着：业务都在服务层，扫码封装成一个接口，以后用 Capacitor 套壳时只换扫码实现。

**为什么不做人事（考勤、排班、工资、绩效）**
和进销存这条主链路没关系，做了也不能让演示更完整。各家公司规则差别大，工资又是敏感数据，演示版不适合碰。真要做先接排班，因为它能和看板的员工业绩对上。

**为什么不做售后、财务总账、审批流、会员营销**
每一个都是一条独立的长链路，做半截不如不做，演示时还容易被问倒。系统里的“后续规划”页列了每一项为什么没做、以后从哪儿接。演示版只做门店每天离不开的：进货、串号库存、调拨盘点、开单收银、回收、日结、看板。

**为什么不做离线**
ERP 数据要实时，两个店员同时卖同一台机器必须有一个失败，离线下单会把这件事推迟到联网时才发现。PWA 只做了“添加到桌面”，没做离线缓存。门店断网时用纸质单据记，联网后补录，这是大多数门店现在的做法。

**为什么服务器还没买**
现在还没开始找工作，服务器和域名按月花钱，备案要 1 到 3 周。所有要服务器的事集中放到“找工作前再做”，第一次面试前约 3 周开始。没上线前用本机演示，手机测试用本机临时 HTTPS。
