# 安全基线逐项核对

对照方案 6.6。“本机”是现在已经做到并核对过的；“上线时”是买了服务器之后在任务清单“找工作前再做”里做的。

| # | 要求 | 状态 | 怎么做到的 / 在哪 |
|---|---|---|---|
| 1 | 密码哈希存储 | 本机已做 | bcrypt 10 轮，`src/server/auth/password.ts`；库里只有哈希 |
| 2 | 登录接口限流 | 本机已做 | 按用户名：15 分钟错 5 次锁 15 分钟（`src/server/auth/login-service.ts`），不信任可伪造的 X-Forwarded-For，IP 只记日志；4 个公开演示账号不限流；自己改密码时旧密码错也走同一套 |

另外做了的：

- 会话 cookie：`httpOnly`（页面脚本读不到）、`sameSite=lax`（别的网站带不过来）；`Secure` 按这次请求实际是不是 HTTPS 决定（Caddy 会带 X-Forwarded-Proto），备案前用 http://服务器IP 也能登录，也可以用 COOKIE_SECURE=1/0 强制。
- 账号被停用后，浏览器里的旧 cookie 会被清掉再回登录页（`/api/session/clear`），不会在登录页和首页之间无限跳转。
- 成本字段按角色在服务层去掉（店员拿不到采购价和参考成本），采购单只有总部能看。
- 客户搜索：姓名和手机号都能模糊搜，手机号至少输 4 位（2026-10-17 坤总定）。已知取舍：能模糊搜手机号，有心人可以一位一位试出被脱敏的中间 4 位；只有店员、店长、总部能搜，演示版接受。
- 数据权限在服务层：每个查询按角色加门店条件，越权直接拒绝（`src/server/auth/scope.ts`），不靠前端隐藏按钮。
- 安全响应头（`next.config.ts`）：不许被别的网站套 iframe、不乱猜文件类型、跳外站不带完整地址、只允许本站用摄像头；去掉 `X-Powered-By`。
- 所有写操作记操作日志（谁、什么时候、对哪条记录），总部在 `/logs` 查。
- 生产环境启动检查（`src/instrumentation.ts` → `src/server/config-check.ts`）：会话密钥少于 32 个字符、还是示例占位值、没配数据库，或数据库密码是示例值，就打印原因并拒绝启动。

并发和数据完整性（2026-10-17 代码审查后补）：

- 机器状态条件写入：只有状态没被别人改过才更新，同一台机器不会被卖两次、调两次（`src/server/stock/stock-service.ts`）。
- 配件原子增减：出库“余额够才减”，数据库 CHECK 约束保证余额不为负。
- 单据级排队：调拨发出、作废先“抢”状态（只有还在申请中才改）；调拨收货、采购入库 / 改单 / 作废、盘点录入 / 确认先锁住单据行再核对（`src/server/db-lock.ts`）。两个标签页同时点、两个人同时操作，都只做一次。
- 同店同日排队：开单、作废、退货、日结保存 / 确认 / 撤销先拿“门店 × 营业日”的锁（`src/server/dailyclose/guard.ts`），日结算账时不会插进新单，同一张单不会被同时作废两次。
- 数据库检查约束（迁移 `integrity_checks`、`review_fixes`）：采购、调拨明细的已收数量在 0 到应收之间；配件余额 ≥ 0；收款明细必须且只能属于销售单或退货单之一；已退数量在 0 到售出数量之间。
- 唯一约束（迁移 `item_device_unique`）：一台机器在一次盘点、一张调拨单里只能有一行。
- 重复的码撞上唯一约束时提示“已经在系统里了”，不再只显示“操作失败”。
- 收银日报导出防公式注入：以 = + - @ 开头的文字前加单引号，金额不受影响（`src/lib/csv.ts`）。
- 测试：机器一机两卖、配件超卖、同店同日排队、余额不为负由 `tests/concurrency.db.test.ts` 覆盖（让两个事务真的同时跑，换回旧代码时前两条会失败）；CSV 转义由 `tests/csv.test.ts` 覆盖。日结和开单交错、重复码提示没有单独写并发测试，靠同一把锁和数据库约束保证。

没做的和原因：

- CSP（内容安全策略）：Ant Design 的样式是运行时注入的，严格 CSP 要给每个请求配 nonce，演示版先不做。
- 登出后让旧令牌立刻失效：令牌是无状态的 JWT，7 天过期；要立刻失效得在库里记黑名单，演示版不做。
